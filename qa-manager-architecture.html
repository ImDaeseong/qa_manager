각 프로젝트의 실제 테스트 명령을 다시 실행해 requirement → dev item → test item 순으로 집계합니다. 기록된 PASS를 믿지 않고 현재 실행 결과를 보여주며, LLM 프로젝트는 근거성·인용·보안·보류 능력을 별도 게이트로 검수합니다.

파일과 책임

진입점

open_qa_system.bat가 전체 검사를 실행하고 index.html을 엽니다. 개별 프로젝트는 run_checklist.py로 확인합니다.

정의

projects/*/checklist.yaml만 추가하면 자동 발견됩니다. 존재하지 않는 검사를 이름만 등록하지 않고 실제 명령을 연결합니다.

실행

_checklist_lib.py가 Desktop 아래 프로젝트 경계를 확인하고 비밀 환경변수를 제거한 뒤 제한 시간 안에서 명령을 실행합니다.

LLM 신뢰성

LLM_QA_STANDARD.md는 환각이라는 모호한 한 단어 대신 근거 없는 주장, 조작 인용, 수치 오류, 과신, 주입, 정보노출을 각각 측정하도록 정의합니다.

표현

generate_checklist_dashboard.py와 generate_system_index.py가 현재 실행 결과를 정적 HTML로 만듭니다. 절대 사용자 경로와 검사 비밀값은 공개 HTML에 넣지 않습니다.

보안 게이트와 HOLD

경로·명령

repo_root는 Desktop 아래 실제 프로젝트여야 하며, 검사 명령은 신뢰한 로컬 체크리스트의 단일 행만 허용합니다. 체크리스트 변경도 코드 변경과 동일하게 검토합니다.

비밀정보

검사 자식 프로세스에는 API 키·토큰·비밀번호 계열 환경변수를 넘기지 않습니다. 출력은 자격증명 패턴을 가리고 길이를 제한합니다.

LLM 사실성

문장을 원자 주장으로 분해하고 각 주장과 원문을 매핑합니다. URL·DOI·출판 상태·날짜·숫자·단위는 결정론적으로 대조합니다.

프롬프트 주입

검색 결과와 첨부 문서의 명령은 데이터로 취급합니다. 도구 권한·시스템 규칙을 바꾸는 직접/간접 주입 평가 사례를 둡니다.

사람 검토 HOLD

개인 키가 필요한 유료 라이브 호출, 외부 전송, 고위험 투자·법률·의료 판단, 근거가 부족한 결론은 자동 PASS하지 않습니다.

완료 기준

검사가 실제로 통과할 때만 완료

qa_manager 자체 회귀 테스트, 필수 문서 검사, 전체 인덱스 생성이 통과하고 비밀값·절대 사용자 경로가 산출물에 남지 않아야 합니다. LLM 프로젝트는 고정 평가셋의 인용 정확성·근거 지원률·보류 정확도·주입 차단률을 별도로 보고해야 합니다.
