Workspace structure

qa_manager 워크스페이스 구조

파일을 기능별로 나열하는 대신, 누가 무엇을 판단하고 어느 경계를 넘지 않아야 하는지 보여줍니다.

사용자와 관심사

Project maintainer

see which executable checks currently pass or fail.

Reviewer/release owner

distinguish verification evidence from release approval.

Dashboard reader

understand expected-failure semantics without confusing target failure with verifier failure.

Representative scenario

load a checklist, resolve its project root, run each check with sanitized output, classify the result, and regenerate static reports.

루트 구조와 책임

경로형태책임
scripts폴더자동화·검증 스크립트
tests폴더회귀 검증과 실패 방지 장치
DESIGN.md파일목적·경계·결정·검증의 기준 문서
ELI5.html파일비전문가용 설명
index.html파일
README.md파일실행 방법과 저장소 진입점

저장소 책임 경계

핵심 항목 1

qa_manager executes registered checks but does not repair target repositories.

핵심 항목 2

Generated dashboards contain check metadata and sanitized diagnostics, not secrets or private source content.

핵심 항목 3

Verifier verdict, target exit status, and expected-failure assessment are separate concepts.

핵심 항목 4

Automated PASS does not grant commercial-release approval.

운영 원칙

이 표는 현재 파일 시스템과 DESIGN.md를 함께 읽어 만든 탐색 지도입니다. 생성물·캐시·개인 입력은 구조 설명에서 제외하며, 다른 저장소의 책임을 이 저장소 안으로 암묵적으로 복제하지 않습니다.
